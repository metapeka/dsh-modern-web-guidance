Модели по умолчанию пишут веб-код по своему обучающему срезу — то есть тянут паттерны пятилетней давности. Этот
плагин кладёт перед агентом 208 курируемых, экономных по токенам гайдов и офлайн-поиск по ним, чтобы он брал актуальный
API платформы (нативные `<dialog>`/popover, anchor positioning, container queries, view transitions, scroll-driven
эффекты, `:has()`, passkeys, `fetchpriority`, …), а не костыль на JavaScript или библиотеку.

Всё работает локально: гайды лежат внутри пакета, поиск считается в процессе, сетевых вызовов нет. Счётчики
использования есть с 0.2.0, но они не покидают машину — см. [Статистика использования](#usage-stats).

<a id="what-you-get"></a>

## 🧰 Что вы получаете

| Тип | Имя | Описание |
|---|---|---|
| Инструмент | `web_guidance_search` | Ранжированные id гайдов по запросу из 2–5 слов, опционально с фильтром по категории |
| Инструмент | `web_guidance_retrieve` | Полный markdown одного или нескольких гайдов (до 10 гайдов / 120k символов за вызов) |
| Инструмент | `web_guidance_list` | Обзор каталога: счётчики по категориям или id и заголовки одной категории |
| Инструмент | `web_guidance_legacy_scan` | Маркерный скан явно перечисленных путей на legacy-паттерны; находит и ничего не меняет |
| Скилл | `modern-web-guidance` | Рабочий процесс: найти → достать → реализовать → проверить → раскрыть фолбэк |
| Скилл | `chrome-extensions` | Разработка Manifest V3 и требования Chrome Web Store |

Сканер работает только на чтение, и читает он только код. `web_guidance_legacy_scan` принимает `paths` (1–16 файлов
или каталогов, цели по умолчанию нет), необязательный список `rules` до 33 id правил и `format: 'summary' | 'json'`; за
вызов он читает не более 200 файлов, до 512 kB на файл и 8 MB суммарно, и возвращает не более 200 находок. В списке
разрешённых расширений 18 кодовых — `.js`, `.jsx`, `.ts`, `.css`, `.html`, `.vue`, `.svelte`, `.astro`, `.json` и им
подобные — и markdown среди них нет: файл `.md` или `.mdx` попадает в пропущенные, а не в прочитанные, потому что
документ, который цитирует антипаттерн, — это документация, а не legacy-код. В каталоги с точкой в начале он тоже не
заходит: привычные (`.git`, `.turbo`, `.next`, `.cache`) перечислены в его собственном списке пропуска, а любой
другой — `.github`, `.vscode` — возвращается одним пропуском `dot-directory` вместо чтения. В таблице 33 правила, из
них 30 — правила апстрима; чего до сих пор не хватает и в чём единственный настоящий долг — в
[заметке о соответствии](docs/notes/legacy-scan-parity.md).

Рабочая папка может сама сказать, что для неё «здесь». `.scanignore` в её корне перечисляет пути, которые скан
трогать не должен: по шаблону на строку, `#` — комментарий, `report/` — все каталоги с таким именем, `src/app.js` —
один файл, `*` — внутри одного сегмента, без отрицаний, без `**` и без `?`. Файл читается в начале каждого скана,
кривая строка попадает в отчёт (`Ignored 1 line in .scanignore (line 7: bad pattern)`), а нечитаемый файл скан не
останавливает. Границей безопасности он при этом не является: сканер и так заперт в рабочей папке, так что игнор может
только уменьшить прочитанное.

```text
# .scanignore — не трогать сборку и сваленные дампы
tmp-deploy/
report/
*.min.js
```

Так или иначе, итог говорит, что именно пропущено и почему: `Skipped 279 path(s): 277 extension, 2 dot-directory` на
этом репозитории — `path(s)`, а не `file(s)`, потому что пропущенный каталог считается одной записью, а не каждой
строкой внутри него.

Тот же скан доступен человеку командой `/guidance-scan <paths> [--rules ls-01,ls-13] [--format summary|json]`: она
ходит через тот же сканер, с теми же отказами и лимитами, и не запускается без хотя бы одного явного пути. Кнопка
сканирования в панели — та же операция, где `.` уже подставлен: она проходит по всем кодовым файлам рабочей папки
сессии, а прозу пропускает.

Каталог покрывает `css`, `ui-atoms`, `ui-components`, `ui-behaviors`, `forms`, `html`, `js`, `accessibility`,
`visual-design`, `security`, `performance`, `built-in-ai`, `pwa`, `wasm`, `webmcp`, `privacy` и `user-experience`.

<a id="install"></a>

## 🚀 Установка

Из опубликованного пакета:

```shell
dsh plugin --profile desktop add dsh-modern-web-guidance
```

Из GitHub:

```shell
dsh plugin --profile desktop add github:metapeka/dsh-modern-web-guidance
```

Из локальной копии (реестр не нужен):

```shell
dsh plugin --profile desktop add file:E:/path/to/dsh-modern-web-guidance
```

Из сессии агента то же самое делает `plugin_manager` с `action: "install_bundle"` и абсолютным путём к пакету в
`target`. Бандл добавляет одну строку (`modern-web-guidance`) и не требует сборки, зависимостей или нативных модулей.

<a id="how-to-use"></a>

## 🧭 Как пользоваться

Ничего настраивать не нужно: плагин регистрируется сам, а скилл `modern-web-guidance` подсказывает агенту, когда к
нему идти. Есть три способа работы.

<a id="which-tool-when"></a>

### Каким инструментом когда

| Что нужно | Вызов | Что вернётся |
| --- | --- | --- |
| «как это делается сегодня?» | `web_guidance_search` | ранжированные id гайдов по запросу из 2–5 слов, опционально с фильтром по категории |
| «покажи гайд» | `web_guidance_retrieve` | полный markdown, до 10 гайдов или 120 000 символов за вызов |
| «что там вообще есть?» | `web_guidance_list` | счётчики по категориям или id и заголовки одной категории |
| «каталог вообще используется?» | `/guidance-stats` | локальный отчёт текстом; `--json` — это то, что читает панель |
| «код, который я собираюсь написать или проверить, не тянет legacy-паттерн?» | `web_guidance_legacy_scan` | находки по явно перечисленным путям, до 200 за вызов |
| «хочу прогнать проверку сам, из терминала» | `/guidance-scan src/` | те же находки текстом; `--format json` даёт машинное значение, `--rules ls-01,ls-13` сужает таблицу |

### 1. Просто попросить сделать веб-задачу (обычный режим)

Описание скилла для роутинга — «искать по 208 гайдам, прежде чем писать HTML, CSS или клиентский JavaScript», так что
обычного запроса достаточно: агент ищет, достаёт нужное и пишет код под актуальный API платформы вместо костыля:

```text
Вы: Добавь модальное окно настроек, которое закрывается по клику вне его.

Агент: web_guidance_search({"query": "light dismiss dialog"})
        → light-dismiss-a-dialog, platform-controls-dismiss-dialog, dialog, …
        web_guidance_retrieve({"ids": "light-dismiss-a-dialog,dialog"})
        → полные гайды с примерами closedby/commandfor и Baseline-фолбэками
```

### 2. Попросить явно

Когда нужна гарантия — или когда агент прошёл мимо поиска на задаче, где он явно уместен:

- «посмотри в modern web guidance, как это делается сегодня»
- «сверься с гайдами, прежде чем писать этот CSS»
- «проверь, что это Baseline, и покажи фолбэк»
- «найди гайд про light-dismiss диалоги и следуй ему»

### 3. Посмотреть каталог самому

`web_guidance_list` отвечает на вопрос «что там вообще есть», не тратя вызов на извлечение гайда:

```text
web_guidance_list({})                             → 208 гайдов в 17 категориях
web_guidance_list({"category": "css"})            → 18 CSS-гайдов по id и заголовкам
web_guidance_search({"query": "view transition"}) → ранжированный список до извлечения
```

Фильтр по категории прощает огрехи (`" CSS "` и `"Css"` означают `css`), а категория с опечаткой возвращает список
настоящих категорий вместо пустого ответа.

### Типовые задачи

| Что нужно | Запрос, который может использовать агент | На какой гайд попадёт |
|---|---|---|
| Модалка, закрывающаяся по клику вне её | `light dismiss dialog` | `light-dismiss-a-dialog` |
| Чтобы страница не скроллилась под модалкой | `prevent page scroll under modal` | `prevent-page-scroll-under-modal-dialog` |
| Таблица, работающая на телефоне | `responsive data table` | `responsive-table` |
| Переключение светлой и тёмной темы | `dark mode toggle` | `dark-mode-toggle` |
| Ползущий индикатор вкладки без JavaScript | `anchor positioning` | `anchor-positioning-tab-underline` |
| Валидация, которая не придирается во время ввода | `form validation after interaction` | `validate-input-after-interaction` |
| Вход без пароля | `passkey registration` | `passkey-registration` |
| Быстрый LCP | `prioritize hero image` | гайды про `fetchpriority` |
| Расширение Manifest V3 | (скилл) `chrome-extensions` | материалы скилла про расширения |

<a id="vs-google"></a>

## 🆚 Против пакета Google

Этот плагин **вендорит корпус Google** — те же 208 гайдов, побайтово идентичных — и добавляет слой, который нужен
DeepSeek Harness: инструменты для модели, боковую панель и никаких зависимостей рантайма. Он не переписывает их агента
и сознательно отказывается от движков, которые не выжили бы при бюджете размера и безопасности плагина. Честное
разделение:

| | Google `modern-web-guidance` | Этот плагин |
| --- | --- | --- |
| Форма | npm-пакет: CLI плюс скиллы, запуск как `npx -y modern-web-guidance@latest …` | плагин DSH: 4 инструмента, 2 скилла, 2 человеческие команды, боковая панель |
| Аудитория | любой агент, умеющий запускать команды в оболочке | сессии DeepSeek Harness |
| Корпус гайдов | 208 проиндексированных гайдов (209 файлов `.md`, один побайтовый дубль) | те же 208, побайтово идентичны, срез `2026_11_09-5bcc021b` |
| Поиск | предвычисленные ассеты в `gen/` — квантованные векторы слов (`query-words.i8`, 7.47 MB) и эмбеддинги чанков, 9.16 MB вместе | BM25 строится в процессе из `guides.json` и тел гайдов: без ассетов, без скачивания модели (измерено 29/30 top-1 на пробе из 30 запросов) |
| Зависимости рантайма | Node плюс движки CLI, поставляемые в пакете | нет |
| Сеть | `npx` скачивает пакет, дальше всё локально | никогда — корпус лежит внутри пакета |
| Сканер legacy | движок `legacy-scan` на 4.99 MB с четырёхшаговым процессом scan → verify → report → modernize | поставляется с 0.5.0: сканер регулярными выражениями без зависимостей, 33 правила, из них 30 — правила апстрима, только явные пути, только отчёт; с 0.7.0 у него есть человеческая команда `/guidance-scan`, а с 0.7.1 он читает только код |
| Экспериментальные гайды | закрыты внутри CLI | маркер `[experimental]` в `web_guidance_search`, предупреждающий баннер в `web_guidance_retrieve` |
| Анализ использования | нет | локальные счётчики, отчёт `/guidance-stats`, команда `/guidance-scan` и панель, которая показывает и то и другое |
| Языки | гайды на английском | те же гайды; документация на EN/RU/ZH, панель на EN/RU/ZH |
| Размер | — | 256 файлов, 901 kB в упаковке, 2.6 MB распакованного |

Что это значит на практике: если вы работаете вне DeepSeek Harness, берите их пакет — это референсная реализация, и
корпус принадлежит им. Внутри Harness нужны инструменты в списке инструментов модели, установка без сборки и без сети и
панель, которая говорит, используются ли гайды; это и есть этот плагин.

<a id="how-search-works"></a>

## 🧠 Как работает поиск

`lib/guidance.js` при первом использовании строит BM25-индекс по встроенному корпусу (~1.9 MB markdown, индексация
занимает несколько сотен миллисекунд, дальше кэш): заголовок, id, описание, `featuresUsed`, заголовки разделов и
текст, со стоп-словами, небольшим английским стеммером, префиксным расширением и бонусами за точное совпадение id или
заголовка. Никаких эмбеддингов, встроенной модели и TensorFlow.js — пакет остаётся компактным, а каждый результат
объясним.

По сравнению с семантическим поиском апстрима фразовые запросы (`"light dismiss dialog"`, `"anchor positioning"`)
ставят на первое место нужный гайд; на широких тематических запросах порядок может отличаться. Если поиск промахнулся,
`web_guidance_list` покажет, что в каталоге есть.

<a id="experimental-guides"></a>

## 🧪 Экспериментальные гайды

Восемнадцать из 208 гайдов описывают возможности платформы, которые нельзя считать безопасными: восемь закрыты Origin
Trial в Chrome, а десять изменчивы в пределах одного движка. Апстрим помечает их в своём индексе; этот плагин показывает
пометку там, где агент её действительно увидит:

- `web_guidance_search` добавляет `[experimental]` к результату;
- `web_guidance_retrieve` открывает гайд баннером `> [!WARNING]`, называющим причину;
- тело гайда не тронуто — побайтово идентично апстриму — а баннер считается в бюджет 120 000 символов, а не в лимит
  в 10 гайдов.

<details>

говорите пользователю, какая часть за флагом, прежде чем это отгружать.

<a id="skills"></a>

## 🪄 Скиллы

Тело скилла `modern-web-guidance` адаптировано из апстрима: он велит агенту вызывать инструменты этого плагина вместо
CLI через `npx`, сохраняет заметки про фреймворки/SSR/DOM и политику Baseline-фолбэков, убирает разделы про CLI и
телеметрию и проговаривает границу доверия — извлечённые гайды это справочный материал, а не инструкции. Скилл
`chrome-extensions` вложен без изменений и подгружает свои файлы из `references/` внутри каталога скилла.

<a id="security-and-limits"></a>

## 🛡 Безопасность и границы

Корпус — это сторонний текст, который попадает в контекст модели, а аргументы инструментов приходят от самой модели,
поэтому ограничены обе стороны:

- **Ни сети, ни исполнения, одна локальная запись.** Плагин импортирует только локальные `node:fs`, `node:fs/promises`,
  `node:path`, `node:url` и `node:buffer`; у него нет зависимостей и lifecycle-скриптов, поэтому при установке ничего
  не скачивается и не выполняется. Единственный файл, который он пишет, — собственный файл счётчиков (см.
  [Статистика использования](#usage-stats)).
- **Гайды не могут протащить команды.** В телах гайдов апстрима есть перекрёстные ссылки вида
  `npx -y modern-web-guidance@latest retrieve "…"` (197 вхождений в 64 гайдах). При загрузке индекса они
  переписываются в `web_guidance_retrieve({"ids":["…"]})`, так что ничто прочитанное моделью из каталога не просит
  её установить и выполнить непинённый удалённый пакет. Файлы на диске остаются побайтово равны закреплённому срезу.
- **`web_guidance_retrieve` ограничен**: не более 10 гайдов и 120 000 символов за вызов, повторяющиеся id
  схлопываются, эхо несуществующих id обрывается на 10, а рендерер прямо говорит, что не вернул и что нужно запросить
  отдельно. Извлечение всех 208 гайдов отдало бы 1.9 MB (~475k токенов) одним результатом.
- **`web_guidance_search` ограничен**: запрос обрезается до 512 символов и 24 уникальных термов до лексического
  прохода. Запрос на 137 KB раньше блокировал event loop хоста на секунды; та же форма теперь стоит миллисекунды.
- **Сканер читает только то, что ему дали.** У `web_guidance_legacy_scan` нет цели по умолчанию: вызывающий называет
  1–16 путей, каждый обязан разрешаться внутри воркспейса сессии, а симлинк, уводящий наружу, пропускается, а не
  читается. Абсолютные пути, пути за пределами воркспейса и отсутствующие пути он отклоняет (`path-absolute`,
  `path-outside`, `path-missing`), чтение ограничено 200 файлами, 512 kB на файл и 8 MB на вызов, и он не пишет ни байта.
  Читает он при этом только код: `.md` и `.mdx` не входят в список разрешённых расширений, поэтому проза возвращается
  как пропущенная, а не как находка. Человеческая команда `/guidance-scan` идёт через тот же сканер, поэтому отклоняет те
  же пути и держит те же лимиты; она ещё и не запускается без пути, так что случайно пройтись по всему воркспейсу нечем.
- **Каталог не может выйти за пределы пакета**: id и категории записей обязаны быть слагами, и каждый разрешённый путь
  проверяется на принадлежность каталогу данных. Подменённый `guides.json` раньше мог прочитать любой `*.md` на диске.
- **Сбои повторяются и не раскрывают лишнего**: случайная ошибка чтения больше не отравляет инструмент на всю сессию,
  а тексты ошибок не выдают абсолютные пути установки.

Эти свойства закреплены в `test/hardening.test.mjs`, который падает на коде до этих правок, а изоляция и лимиты
сканера — в `test/scan-core.test.mjs`. Полный аудит — три отчёта и запускаемые репро — лежит в [`audit/`](audit/);
скрипты в `audit/repro/` завершаются с ненулевым кодом, пока дефект жив.

<a id="usage-stats"></a>

## 📊 Статистика использования

С версии 0.2.0 плагин записывает, что именно спрашивают у четырёх инструментов. Счётчики локальные: ни endpoint, ни аналитического
сервиса, ни стороннего SDK — за пределы машины ничего не уходит.

Отчёт смотрит человек командой, а не инструментом, который может вызвать агент:

```text
/guidance-stats                 итоги по инструментам за последние 7 дней
/guidance-stats --days 30       более широкое окно
/guidance-stats --json          тот же отчёт в JSON
/guidance-stats --reset --yes   стереть всё
```

`--days N` по умолчанию 7. Что считается: вызовы по инструментам, исходы (hit, miss, unknown id, list, error),
счётчики по дням, попадания по категориям, извлечения по гайдам и последние 1000 вызовов с текстом запроса и
возвращёнными id. Промахи как раз и нужны — промах, который нельзя воспроизвести, нельзя исправить.

0.5.0 добавляет в тот же отчёт четвёртую строку (`legacy-scan`) и итог по находкам. 0.7.0 добавляет к этому
детализацию: какие правила и гайды дали находки, и последнее завершённое сканирование — когда, сколько файлов
прочитано, сколько находок; в отчёте это строки `Most matched rules: …` и `Last scan: …`. Только id и числа, ни
путей, ни сниппетов.

Где лежит: durable-хранилище профиля — та же граница доверия, где уже лежат логи сессий. Срок хранения по умолчанию
90 дней, `--reset --yes` стирает всё.

Как выключить: `enabled: false` в конфиге плагина — тогда слушатель не регистрируется и файл не пишется.

<a id="sidebar-panel"></a>

## 🖥 Боковая панель

Плагин добавляет клиентскую часть: иконка в левом рейле открывает в центральной области панель
**Guidance Insights**. Это те же счётчики, что печатает `/guidance-stats`, но в виде карты: панель отвечает на
четыре вопроса по порядку:

- **сколько и насколько удачно** — всего вызовов и доля попаданий, посчитанная по вызовам, которые вообще могли
  попасть (попадания поиска, промахи поиска, неизвестные id); доля «по всем вызовам», как её считает отчёт, лежит в
  подсказке плитки. Переключатель `7 дн.` / `30 дн.` перечитывает окно
- **когда** — вызовы по дням, по столбику на день окна
- **чем и с каким исходом** — вызовы по инструментам и по исходам, рядом
- **что находит сканер** — последнее завершённое сканирование, чаще всего сработавшие правила (до 10) и гайды, на
  которые указывают эти находки; кнопка ниже прогоняет сканер по всем кодовым файлам рабочей папки сессии (markdown
  пропускается и показывается как пропущенный) и показывает результат этого прогона тут же

Дальше идут списки из отчёта: частые запросы с попаданиями и промахами, покрытие категорий против 208 гайдов,
запросы без результата и непрочитанные гайды — списком id, до 20.

Обновление перечитывает счётчики, а переключатель `7 дн.` / `30 дн.` отправляет хосту
`/guidance-stats --json --days N`. В диалоге сканирование показывается таблицей — правило, место, уверенность,
гайд — до 16 строк и «и ещё N», в каком бы формате его ни запросили.

Панель только читает, кроме кнопки сканирования: она не меняет счётчики и не покидает машину, сетевых вызовов и
новых инструментов не добавляет — четыре инструмента остаются ровно четырьмя. Запущенное из неё сканирование
считается как любое другое. Путей и сниппетов в панели нет намеренно: панель показывает счётчики, а не
доказательства, — файлы и строки видны в строке вызова в диалоге. `/guidance-stats` остаётся текстовой версией (в том
числе `--json`) для терминала и агента, а `/guidance-scan` — текстовая пара кнопки.

<a id="configuration"></a>

## ⚙️ Конфигурация

Настройка не нужна, чтобы плагин работал. Он регистрирует инструменты и скиллы на контексте хоста и бездействует,
если в профиле нет сервисов `tools` или `skills`. Единственная настройка — `enabled` в конфиге плагина: `false`
выключает локальные счётчики, а вместе с ними и `/guidance-stats`; `/guidance-scan` продолжает работать, потому что
сканирование — не подсчёт (см. [Статистика использования](#usage-stats)).

<a id="updating-the-guide-corpus"></a>

## 🔄 Обновление корпуса гайдов

Корпус — это закреплённый срез апстрима `modern-web-guidance@1.0.0` (версия скилла `2026_11_09-5bcc021b`). Чтобы
обновить:

1. Скачайте npm-тарбол апстрима. Индекс лежит в `gen/`, а не в корне пакета: скопируйте
   `package/skills/modern-web-guidance/gen/guides.json` в `data/guides.json`, а
   `package/skills/modern-web-guidance/guides/` в `data/guides/`. Кладите в пакет только гайды из этого индекса
   (208 из 209 файлов: `built-in-ai/prompt-api.md` — побайтовый дубль `language-model.md`, в индексе его нет).
   `package/skills/chrome-extensions` скопируйте в `data/skills/`.
2. Сохраните `data/skills/modern-web-guidance/SKILL.md` — это адаптированная версия этого плагина, не перезаписывайте
   её файлом апстрима, заточенным под CLI.
3. Запустите `npm test`, чтобы убедиться, что корпус грузится и дымовые запросы по-прежнему ранжируются правильно.
   Тесты также падают, если какой-то отданный гайд велит агенту запускать CLI апстрима, поэтому после обновления не
   нужен ручной проход «убрать npx» — переписывание происходит при загрузке (`lib/guidance.js`, `CLI_REFERENCE`).

<a id="faq"></a>

## ❓ Частые вопросы

**Плагин установлен, но я ничего не вижу.** Бандл добавляет одну строку (`modern-web-guidance`) и не требует сборки.
Перезапустите DSH после `dsh plugin --profile desktop add …`; инструменты появятся в списке инструментов следующей
сессии, а панель — иконкой в левом рейле.

**Поиск не находит ничего полезного.** Запрос — это 2–5 слов, описывающих возможность («light dismiss dialog»,
«view transition», «container query»), а не предложение. Если запрос всё равно промахнулся, вызовите
`web_guidance_list` для обзора по категориям и оттуда извлекайте по id.

**Почему в результате `[experimental]`?** Платформенная возможность гайда закрыта Origin Trial или изменчива в одном
движке — см. [Экспериментальные гайды](#experimental-guides). Гайд всё равно задаёт правильную форму; проверьте её
фича-детектом, прежде чем отгружать.

**Что сканер legacy вообще умеет?** Это маркерный скан регулярными выражениями, а не парсер: 33 правила проверяются
построчно и покрывают 33 из 208 гайдов (15,9 %), без AST, без анализа потока данных и без автоисправлений — он
отчитывается и останавливается. Читает он код, а не прозу: 18 кодовых расширений, и файл `.md` пропускается с причиной
`extension`, даже если назвать его явно, — README, который цитирует антипаттерн, это документация. Паритета с
собственным `legacy-scan` Chrome он не заявляет: там движок на 4.99 MB со
встроенным компилятором TypeScript, здесь — проход без зависимостей, который может и ошибиться, и пропустить; считайте
находку зацепкой для проверки, а не вердиктом.

**Что-нибудь уходит с моей машины?** Нет. Корпус лежит внутри пакета, поиск считается в процессе, сетевых вызовов нет.
Счётчики использования — локальные файлы, их можно выключить через `enabled: false` — см.
[Безопасность и границы](#security-and-limits) и [ADR 0001](docs/adr/0001-local-telemetry.md).

**Google говорит про 203 use case. Почему здесь 208?** Собственный счёт апстрима — 203 *use-case* гайда; в индексе
208 записей, лишние пять — обзорные гайды дисциплин (`accessibility`, `forms`, `html`, `performance`, `security`). Этот
плагин поставляет то, что в индексе.

**Какие версии DSH подходят?** `engines.dsh` — `>=0.2.0-rc.1 <0.3.0-0`, Node `>=22.19.0`. Инструменты работают сами по
себе; панели дополнительно нужны сервисы хоста `slots`, `locale` и `remote`.
