# 0.6.0 — three more legacy rules, and a guard that keeps them honest 🛡

The scanner now matches **33 legacy markers over 33 guides** and reaches **30 of upstream's 35 rules**, closing
three of the eight gaps 0.5.0 left open; the five that remain are refused, not pending. A dev-only guide-hash
guard makes a corpus refresh fail loudly, and nothing else moves — the scanner still only reports.

## 📚 Corpus

- Unchanged: the same **208 guides** from snapshot `2026_11_09-5bcc021b`, byte-identical, no re-vendor. The
  three rules are metadata over guides already in `data/guides.json`; the other 175 have no legacy twin.

## ✨ Features

- **33 rules over 33 of the 208 guides** (15.9 %): 18 high, 13 medium, 2 low confidence. Three new markers,
  each mechanical, none needing DOM or form context:
  - `ls-31` — `:host-context()` → `styling-web-components`: never standardised, absent from Firefox and
    Safari; inherited custom properties or container style queries replace it.
  - `ls-32` — `balanceText()` and `<Balancer>` → `improve-text-layout-and-legibility`: CSS
    `text-wrap: balance` / `pretty` replaces JavaScript line balancing.
  - `ls-33` — `select:invalid` → `select-menu-interaction`: a required `<select>` styled on `:invalid` paints
    its error state before the user has touched it; `:user-invalid` is the interactive selector.
- **The gap to upstream is 30 of 35**, and the five left over are named rather than promised: four `autofill-*`
  rules need field context (a sign-in, sign-up, payment or address form), and `package-text-balance` reads
  `package.json`. Neither is a regex problem; see
  [`docs/notes/legacy-scan-parity.md`](https://github.com/metapeka/dsh-modern-web-guidance/blob/main/docs/notes/legacy-scan-parity.md).
- **A finding is a lead, not a verdict.** The scanner does not verify a hit, does not rewrite code and makes
  no parity claim with upstream's AST engine; the rule count is bookkeeping, not the metric.

## 🧪 Behaviour changes

- Two rules were **split, not duplicated**: `ls-22` keeps `fitty`/`fitText` for text sizing and no longer
  matches `balanceText`/`<Balancer>`, while `ls-08` keeps `input:invalid`/`textarea:invalid` and no longer
  matches `select:invalid`; those markers now report `ls-32`/`ls-33`, against the guide that addresses them, so
  a scan that was clean in 0.5.0 can return findings where it did not before. The result shape is untouched.

## 🛠 Hardening

- **A corpus refresh fails loudly now.** Every rule names a guide, but nothing structural tied a rule's
  one-line replacement to that guide's text, so a refreshed guide could leave a rule describing advice
  Google had since changed with every test still green. `scripts/hash-guides.mjs` pins the sha256 of each
  rule's guide body, and `test/scan-guides.test.mjs` compares that record with the corpus and fails with the
  rule id and the sentence a human must re-read. The caveat is in the guard's own message: it proves the
  guide moved, not that the rule's replacement still describes it.
- Regenerate with `node scripts/hash-guides.mjs`; check without writing with `--check` (33 rules over 33
  guides, no drift). Both files are dev-only — `scripts/` and `test/` sit outside `package.json` `files` —
  and the scanner's surface is unchanged: explicit relative paths, report-only, no write, spawn or network.
  `AGENTS.md` and `GLOSSARY.md` follow with the `ls-01` … `ls-33` range, and `docs/README.md` sends a rule
  author to the parity note.

## 🧩 Compatibility

- Engine ranges unchanged: DSH `>=0.2.0-rc.1 <0.3.0-0`, Node `>=22.19.0`; no new dependency, no build step. The
  argument schema is the same (`paths`, `rules`, `format`): the three new ids work in `rules`, an unknown id is
  still named back rather than thrown, and 0.5.0 state files are read as-is.

## 📦 Package

- **256 files, 874 kB packed, 2.5 MB unpacked** — the file count did not move: three rules extend
  `lib/scan-rules.js`, and the guard lives in `scripts/` and `test/`, which never ship. Still **zero**
  runtime dependencies, Apache-2.0, sigstore provenance from the release workflow.
