# 0.9.0 — a counter that explains itself 🔎

A ranked rule used to read `ls-17 121`: an id only the source explains, a number with no unit, on a
screen whose period switch does not apply to it. 0.9.0 gives every ranked counter the words it was
missing — its confidence, a count that says `121 findings`, and the rule's own sentence — and adds one
caption saying the ranked totals are lifetime. Same four tools, same 33 rules, same scanner behaviour,
no new dependency.

## ✨ Features

- **A rule row explains itself.** `ls-17 121` becomes `ls-17 · medium · 121 findings` with the rule's
  own sentence — "Build the DOM with createElement/append instead of `document.write()`, which discards
  the parsed document." — clamped to two lines underneath, the whole message in the row's `title`, and
  no second line at all when the host sends none. The confidence token stays raw
  (`high`/`medium`/`low`), like a rule id.
- **A guide chip names its guide.** `html (121)` keeps its visible id and count and carries the
  catalog's `description` as a hover hint, so the ranked hints can be read without a retrieval call.
- **The chat row explains a finding without adding a line.** The scan table reads the per-finding
  `message` and `snippet` it already received as `title`s on the rule and place cells — the two facts
  it used to throw away.

## 🧪 Behaviour changes

- **One caption under "Rules that matched" while the scope is lifetime**: "Lifetime totals, not the
  {days}-day window", naming the window actually selected, so the period switch and the ranked counts
  no longer look like they answer the same question. It is the release's only new panel string, and it
  lands in the English, Russian and Chinese dictionaries in one commit — the parity test fails
  otherwise.
- **`/guidance-stats --json` can carry the meaning.** `renderJson(snapshot, { rules, guides })` adds
  `message`, `confidence` and `guideId` to every `topRules` row, `description` to every
  `topScanGuides` row, and the top-level `scanCountsScope: 'lifetime'`. The command passes both
  tables; `renderJson(snapshot)` with no options still returns the earlier document byte for byte, so
  an older consumer cannot tell the enrichment exists.
- **Nothing in the scanner moved.** Same 33 rules, same caps, same refusals, same text, same finding
  shapes: this release changes what the counters say, not what they count.

## 🧩 Compatibility

- **Version skew costs a caption or a hint, never a row.** A host without the enriched fields leaves
  this panel rendering the terse ids and counts it always did, with no caption. A rule id the current
  table no longer knows keeps its row with empty text, an empty confidence and a null guide — the
  count is still true when its explanation is gone.
- `engines` is unchanged: DSH `>=0.2.0-rc.1 <0.3.0-0`, Node `>=22.19.0`.

## 📝 Skills and docs

- The contract is written down where the next reader looks: `docs/notes/legacy-scan-contract.md`, the
  panel's `docs/notes/client-panel-spike.md`, and the `AGENTS.md` bullet a later panel change has to
  keep true.

## 📦 Package

- **256 files, 913 kB packed, 2.7 MB unpacked**, zero runtime dependencies, Apache-2.0. The file list
  does not move: the growth is source inside `lib/report.js`, `index.js` and `client.js`.
- **257 tests in 15 files** — 256 passed plus one symlink-walk test that skips itself where the host
  forbids creating symlinks.

<details>
<summary>展开</summary>

- 面板让计数器自己解释：`ls-17 121` 变成 `ls-17 · medium · 121 findings`，下面附上规则自己那句话（最多
  两行，完整内容放在 `title`；宿主没有句子就只剩一行）。置信度保持原样，和规则 id 一样不翻译。
- 指南 chip `html (121)` 仍显示 id 与计数，目录里的描述放进 `title` 作为提示。
- 对话里的发现表格把已经收到的 `message` 与 `snippet` 用作规则单元格和位置单元格的 `title`，不再为
  每条发现多加一行。
- 「命中的规则」下方多一行说明：「累计总数，不是最近 {days} 天的窗口」。它点明当前选中的窗口，上方的时间
  切换与排名数字不再看起来在回答同一个问题。这是本版唯一新增的面板字符串，EN、RU、ZH 三份词典同时
  加入。
- JSON 只增加字段：`renderJson(snapshot, { rules, guides })` 为规则行补上 `message`、`confidence`、
  `guideId`，为指南行补上 `description`，并给出 `scanCountsScope: 'lifetime'`；不带参数调用仍然逐字节
  返回旧文档。
- 版本错配只丢一行说明或一个提示，不会丢一行数据：规则表已经不认识的 id 仍然保留计数，只是文字为空。
- 打包：**256 个文件、913 kB、解包 2.7 MB**，**257 个测试 / 15 个文件**（256 通过，1 个在无法创建
  符号链接的环境里跳过），运行时依赖仍为零；扫描器行为没有变化。

</details>
