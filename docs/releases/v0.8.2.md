# 0.8.2 — the mark nobody can see 🫥

0.8.1 shipped a manifest the host refuses to load. Nothing about the code changed between the two: a
UTF-8 byte-order mark was written into `package.json`, the file looks identical in every editor and in
`git diff`, and the install fails with `SyntaxError: Unexpected token`. 0.8.2 removes the mark and adds
the check that would have caught it.

## 🛠 Fix

- **`package.json` no longer starts with a BOM.** The host validates the manifest with `JSON.parse`,
  which throws on a leading `U+FEFF`; `require()` strips the mark and `npm pack` does not mind, so the
  suite and the CI gate were both green while every install of `0.8.1` failed. A DSH install of `0.8.1`
  reports `installation rejected: Cannot validate installed package … SyntaxError: Unexpected token
  '﻿'`, and a published package cannot be corrected in place, so the fix is a new version.
- **A guard now fails on a BOM instead of a user.** `test/plugin.test.mjs` reads the first three bytes
  of every file the host parses — `package.json`, `index.js`, `client.js`, the three locale
  dictionaries and the two corpus JSON files — and asserts they are not `EF BB BF`. Verified by putting
  the mark back: the test goes red with `package.json starts with a UTF-8 BOM; the host parses it with
  JSON.parse, which fails on one`, then green once it is stripped.

## 🧪 Behaviour changes

- **None.** Same four tools, same 33 rules, same caps, same JSON shapes, same panel: 0.8.1's `ls-12`
  narrowing is unchanged, and the only difference a scan can show is that 0.8.2 exists. `0.8.1` is
  deprecated on npm with a pointer here, so `npm install dsh-modern-web-guidance` never lands on it.

## 📦 Package

- **256 files, 908 kB packed, 2.7 MB unpacked**, zero runtime dependencies, Apache-2.0, and
  **245 tests in 15 files** (244 passed plus one symlink-walk test that skips itself where the host
  forbids creating symlinks).
