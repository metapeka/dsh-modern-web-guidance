# 0.12.0 — every record now says whether it still means anything 🔍

Phase E added no capability. It made the records the plugin already keeps reviewable: a lifetime total that
names the day the books opened, an ignore line that is named when it excludes nothing, and a mute list that can
be shrunk by one entry after a plan. Nothing expires on its own; a human retires what no longer describes anything.

## ✨ Features

- **A lifetime total says when the books opened.** `scanCountsSince` is the selected bucket's own start, and for
  an aggregate the oldest contributing bucket's — never the document's, which would date a young workspace before
  it existed. The caption gains `· since 2026-09-14`; a document with no origin renders the 0.11.0 caption.
- **An ignore line that excludes nothing is named.** The walk records, per source line, whether that pattern
  excluded anything, and the report prints `.scanignore: 3 patterns, 1 matched nothing.` Two lines with the same
  effect are counted separately, so the duplicate you may now delete is visible.
- **The mute list can be reviewed and shrunk by one entry.** `/guidance-suppress --review` lists every entry
  with its date and reason against the last scan, and never writes; `--remove <siteId> [--dry-run]` plans one
  removal, and the same line without the flag applies it.

## 🧪 Behaviour changes

- **Absence is stated, never assumed.** `unused` is `null`, never `0` and never an empty list, when the scan was
  truncated, hit a cap or read fewer files than its baseline: an incomplete scan cannot prove a suppression dead.
- **An old counter stays undated rather than borrowing a date.** `normalizeState` no longer stamps `now` onto a
  loaded document without `since`; legacy root counters have no origin, so `_unattributed` and its aggregates are silent.
- **A removal is not a fix.** It un-mutes one site and moves no counter: the counters document is byte-identical
  through a removal, `lastScan.suppressed` keeps the count it was given, and the next scan counts the finding
  again. The words stay apart: muted, unused, resolved — the last one does not exist in the product.
- **A copy that never answers says so.** The live panel pass found that `Копировать JSON` could look dead
  forever, because a clipboard write parked by an unfocused window never settles: the label now races a bounded
  wait and says "The clipboard did not answer". That is not "refused", and a late success does not flip it back.
- **The transcript row each panel action leaves is the accepted price.** `execute` renders every command line the
  panel runs, so a mount and a scan cost one visible JSON block each; a cache or a second data path would be worse.

## 🛠 Hardening

- **The removal writer is narrower than the append writer.** One entry, one invocation, one confirmed rewrite:
  temp-then-rename, every other byte and the entry order preserved, a malformed line preserved exactly, the landed
  bytes re-parsed before the rename, a failed write leaving the file byte-identical, and an unknown id is a no-op.
- **The ignore patterns never reach `stats.json`.** Rows stay in memory on the scan value and only
  `{ patterns, idle }` is persisted — an ignore line is a path fragment and that file is profile-wide.

## 🧩 Compatibility

- **`version` stays `1`.** Every field is additive and absent on an older document, which renders the 0.11.0 panel.
  The four tools are unchanged, there is no new command — review and removal are flags on it — and no new
  dependency and no new chart.

## 📝 Skills and docs

- [ADR-0004](../adr/0004-suppression-removal.md) amends ADR-0003's "never a delete" to *append and one confirmed
  removal*, and states the residual it cannot design away: a removal cannot undo what a previous scan reported.

## 📦 Package

- **258 files, 989 kB packed, 2.9 MB unpacked** — no new module, zero runtime
  dependencies, Apache-2.0.
- **506 tests in 18 files**: 502 passed, four skipped (this machine's symlink limit) — and the final tree ran
  **20 times back to back: 19 green, 1 red**, the red being `EBUSY: resource busy or locked, rmdir` in
  `test/stats.test.mjs`'s own temp-home teardown: a Windows file lock in the harness, not a product failure.

  `.scanignore: 3 patterns, 1 matched nothing.` — это единственное место, где строку файла можно назвать
  простаивающей, и две строки с одинаковым эффектом считаются отдельно, чтобы дубликат был виден.

  `/guidance-suppress --remove <siteId> [--dry-run]` сначала показывает план, а без флага удаляет ровно одну
  запись.
- Отсутствие доказательства не превращается в ноль: `unused` — это `null`, а не `0` и не пустой список, когда
  сканирование было усечено, упёрлось в кап или прочло меньше файлов, чем база; битая строка — это проблема
  разбора, а не «неиспользуемая».
- Старый счётчик остаётся без даты, а не занимает чужую: `normalizeState` больше не ставит `now` документу без
  `since`, дату получает только действительно новый документ или папка, поэтому `_unattributed` и сводки с ним
  даты не печатают.
- Удаление — не исправление: оно снимает заглушение с одного места и не двигает ни один счётчик, документ
  счётчиков остаётся байт в байт, а следующее сканирование снова считает находку находкой.
- Копирование, которое не отвечает, так и говорит: метка гоняется с ограниченным ожиданием и пишет «буфер
  обмена не ответил», это не «отказал», и поздний успех её не переворачивает. Строка команды, которую каждая
  кнопка панели оставляет в транскрипте, — принятая цена, а не недосмотр. Пакет: **258 файлов,
  989 kB в упаковке, 2.9 MB распакованного**, **506 тестов в восемнадцати файлах** (502 прошли,

- 终身合计现在说明账本从哪天开始：`scanCountsSince` 是一个日期，取所选工作区自己的起点，汇总时取其中最早的一个；
  不用文档的开始日期，那会把年轻的工作区标到它存在之前。面板的终身说明加上 `· since 2026-09-14`，而没有起点
  的文档渲染得和 0.11.0 一模一样。
- 什么都不排除的 `.scanignore` 行现在会被点名：报告打印 `.scanignore: 3 patterns, 1 matched nothing.` —— 这是
  产品里唯一允许把某行叫作「闲置」的句子；效果相同的两行分别计数，因此可以删掉的重复行看得见。
- 屏蔽列表可以查看，也可以减掉一条：`/guidance-suppress --review` 把文件与最近一次扫描对照（日期、原因、匹配
  几条、几条未匹配）且不写任何东西；`/guidance-suppress --remove <siteId> [--dry-run]` 先给出计划，去掉
  `--dry-run` 后只删除一条记录。
- 没有证据就不写成零：扫描被截断、触到上限或读到的文件比基线少时，`unused` 是 `null`，不是 `0`，也不是空
  数组；格式坏掉的行是解析问题，永远不会被算作「未匹配」。
- 旧计数器宁可没有日期，也不借用别人的：`normalizeState` 不再给没有 `since` 的文档盖上 `now`，只有真正新建的
  文档或工作区才有日期，因此 `_unattributed` 以及包含它的汇总都不打印日期。
- 删除不是修复：它解除一处屏蔽，不动任何计数器 —— 计数器文档逐字节不变，下一次扫描仍把该发现算作发现。
- 不会应答的复制会说出来：标签与一段有界等待赛跑，并显示「剪贴板没有响应」；这不是「拒绝」，迟到的成功也不会
  把标签翻回去。面板每个动作在对话里留下一行命令，这是被接受的代价，不是疏忽。打包：**258 个文件、
  989 kB、解包 2.9 MB**，**506 个测试 / 18 个文件**（502 通过，4 跳过，都是这台机器无法创建
  符号链接所致），最终代码树连跑 **20 次：19 次通过、1 次失败** —— 失败是 `test/stats.test.mjs` 清理自己的
  临时 home 目录时的 `EBUSY: resource busy or locked, rmdir`，是 Windows 上的测试夹具文件锁，不是产品缺陷；
  单独运行该文件 29 项全过。运行时依赖仍为零。
