# 0.7.2 — the scanner learns which directories are none of its business 🚧

Dot-directories are no longer read, and a workspace-root `.scanignore` says which directories and files to
leave out. The scan text now itemises what it skipped and why — `Skipped 279 path(s): 277 extension, 2
dot-directory` — and a malformed or unreadable `.scanignore` is reported instead of failing the scan. The
tool, its arguments, its caps and its refusal codes are unchanged.

## 🧪 Behaviour changes

- **Dot-directories are never walked.** A directory whose name starts with a dot is skipped with reason
  `dot-directory` — the usual noise names (`.git`, `.turbo`, `.next`, `.cache`) were already in the
  scanner's own skip list, so this now covers `.github` and `.vscode` too. The check runs whether the walk
  meets the directory or a path names it explicitly, and it costs **one** skip entry per directory, not one
  per file inside, so build output and scraped dumps stop inflating a report.
- **`.scanignore` at the workspace root.** One pattern per line, `#` for comments, one-segment patterns
  matching a name at any depth (`report/`), patterns containing `/` anchored at the root (`src/app.js`),
  `*` inside one segment, a trailing `/` for directories only. No negation, no `**`, no `?`. A line
  outside that subset is reported, not fatal: `Ignored 1 line in .scanignore (line 7: bad pattern)`, and an
  unreadable file produces `Could not read .scanignore; the scan ran without ignore patterns.`
- **Skips are itemised per reason.** Right after `Scanned N file(s) …` the summary now says
  `Skipped 279 path(s): 277 extension, 2 dot-directory` — counted over **every** skip, not the 100 that
  the `skipped` sample can carry, and ordered by count so the same scan always renders the same line.
- **This repository, measured**: `.` returns **70 files and 97 findings**, `truncated: false`, skips
  `{extension: 277, dot-directory: 2}`; `lib` alone returns **6 files and 18 findings**. The 97 is still
  mostly the rule table — 61 of them live in `lib/scan-rules.js` and `test/scan-rules.test.mjs`, where the
  markers are data — so it measures what the repo *contains*, not how old its code is.

## 🛠 Hardening

- **A scan can still be truncated, and that is the honest answer.** A real Astro project with 58 source
  files scans `src` as **58 files, 22 findings** before and after this release; scanned as `.` it hits the
  **200-file cap** with 41 findings and stays `truncated: true`, because outside its dot-directories it
  holds **241** candidate files (`tmp-deploy` 82, `report` 66, `src` 58, …). Six lines of `.scanignore`
  naming those artifact directories give **77 files, 22 findings**, all of them in `src` and no truncation.
- **The fix for truncation is `.scanignore`, not a bigger cap.** The cap stays at 200 files precisely so a
  scan of a wrongly-shaped workspace cannot turn into a tarball of every asset the repo ships.

## 🧩 Compatibility

- Same tool, same arguments, same caps, same refusal codes; the only text that changed is the new
  `Skipped … path(s)` line and the two `.scanignore` diagnostics. `scanned.skippedByReason` and
  `scanned.ignoreProblems` are **additive** fields inside the same result; state files and counters are
  untouched, and a `.scanignore` diagnostic is never counted as a file skip.
- **`.scanignore` is not a security boundary.** It is a convenience for a project that knows what it means
  by "here", and the scanner is already confined to the workspace by `realpath` containment — an ignore
  file can only make it read less than it was allowed to.

## 📦 Package

- **256 files, 901 kB packed, 2.6 MB unpacked** (measured by `npm pack --dry-run`) — no file added or
  removed, still **zero** runtime dependencies, Apache-2.0, sigstore provenance from the release workflow.

## 🇷🇺 Коротко по-русски

<summary>Развернуть</summary>

- Сканер больше не заходит в каталоги, чьё имя начинается с точки: такой каталог получает причину
  `dot-directory` — одной записью на каталог, а не на каждый файл внутри, и это работает и когда путь
  назван явно.
- В корне рабочей папки читается `.scanignore`: одна шаблонная строка на строку, `#` — комментарий,
  шаблон из одного сегмента совпадает с именем на любой глубине (`report/`), шаблон со `/` привязан к
  корню, `*` не переходит через `/`, слэш на конце — только каталоги.
- Ошибка в `.scanignore` не роняет скан: текст говорит `Ignored 1 line in .scanignore (line 7: bad pattern)`,
  а нечитаемый файл — `Could not read .scanignore; the scan ran without ignore patterns.`
- Пропуски теперь перечислены по причинам: `Skipped 279 path(s): 277 extension, 2 dot-directory`, и
  считаются по всем пропускам, а не по 100, которые помещаются в выборку.
- Этот репозиторий: `.` даёт 70 файлов и 97 находок, `{extension: 277, dot-directory: 2}`, `lib` — 6 и 18.
- Скан может остаться обрезанным: у реального Astro-проекта 241 подходящий файл при капе в 200, и лечится это
  `.scanignore` (77 файлов, 22 находки), а не увеличением капа; сам `.scanignore` — не граница безопасности.
