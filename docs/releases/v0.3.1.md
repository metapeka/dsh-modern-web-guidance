# 0.3.1 — the first OIDC publish, and a pipeline that stops guessing 🔐

No plugin behaviour changed. This release exists because the way the package reaches npm changed: the
repository no longer holds an npm token, and the release workflow stopped treating npm's first-minute
`404` as a failure.

## 🛠 Hardening

- The **verify step now polls the registry for five minutes** instead of failing on the first `404`:
  a brand-new package answers `404` and then serves a `0.0.0-stage` placeholder for a minute or two
  while npm creates it.
- The publish path picks its auth from whether `NPM_TOKEN` exists, so the bootstrap publish and the
  OIDC publish are the same workflow rather than two branches of history.

## 📦 Package

- **Published over trusted publishing (OIDC)** with a sigstore provenance statement; no long-lived npm
  token is stored in the repository any more.
- Nothing else moved: same tools, same corpus, same panel.

## 📝 Skills and docs

- The READMEs carry the npm badge.
- `PUBLISHING.md` records the first-publish rules that cost an afternoon: account 2FA, the bypass-2FA
  granular token, the placeholder version, and where the trusted publisher is pinned.

**Install:** `dsh plugin --profile desktop add dsh-modern-web-guidance`
