# 0.8.1 — the scanner stops giving advice that breaks a clamp 🧷

A finding is only worth its fix if the fix is safe. `ls-12`, the 2009-prefixed-flexbox marker, also fired on
the standard clamp block, where "use unprefixed `display: flex`" deletes the truncation the block exists for.
It now flags only the spellings a clamp cannot serve — same 33 rules, same caps, nothing to migrate.

## 🛠 Hardening

- **The rule no longer fires on the line-clamp idiom.** This block is not the 2009 flexbox:

  ```css
  display: -webkit-box;
  -webkit-line-clamp: 3;
  -webkit-box-orient: vertical;
  ```

  `display: -webkit-box` is the block container `-webkit-line-clamp` needs, and
  `-webkit-box-orient: vertical` is how the clamp stacks its lines, so a `display: flex` rewrite would break
  both. `ls-12` reports neither line now. On the live bench project the wrong finding at
  `src/components/ui/PostCard.astro:110-112` is gone: that scan went from **10 findings to 9**, with `ls-12`
  from **1 to 0**.
- **What it still flags cannot be a clamp.** `display: -webkit-flex`, `display: -webkit-inline-flex`,
  `-webkit-box-pack`, `-webkit-box-align`, `-webkit-box-flex`, `-webkit-box-ordinal-group`,
  `-webkit-box-direction`, and `-webkit-box-orient: horizontal` — each of those is prefixed flexbox with no
  clamp reading, so the advice to use unprefixed `display: flex` and `gap` stays correct there. Same rule id,
  same guide (`css-layout`), same `high` confidence, same message text.
- **The cost, stated rather than buried.** Precision was bought with recall: a page that genuinely uses a bare
  `display: -webkit-box` as flexbox is now unreported. A rule is one line regex and cannot see the
  `-webkit-line-clamp` line above the marker, so it cannot tell the idiom from the old spelling, and we chose
  silence on the two spellings the idiom owns. The boundary and its reasoning are recorded in
  [`docs/notes/legacy-scan-parity.md`](../notes/legacy-scan-parity.md).

## 🧪 Behaviour changes

- **This repository still reports 85 findings, and that is a coincidence, not a no-op.** The composition
  moved: `test/fixtures/scan/dirty/styles.css` was retargeted from `display: -webkit-box` to
  `display: -webkit-flex` so the fixture keeps carrying a true `ls-12` marker (the fixture set still returns
  3 files and 8 findings, one of them `ls-12`), a bare `-webkit-box` inside a test comment stops matching, and
  eight prefix spellings added to a test collapse — under 0.8.0's run rule — into a single finding. `ls-12`
  still accounts for **3** findings here, at different places. Re-run the scan and expect the same total with
  a different report.
- **Nothing else in a report moves.** Same 33 rules, same 18 code extensions, same `SCAN_LIMITS`, same
  ordering, same `lines` and `occurrences` fields and the same JSON shape: a diff of two scans differs only in
  `ls-12` entries.

## 📝 Skills and docs

- **`.scanignore` now says it may park a single file** (issue #10): a pattern can name one file rather than a
  directory, and that file is skipped while its siblings are read — measured on a workspace of three pages
  with one named, 2 files and 2 findings with one `scanignore` skip. Naming the parked path explicitly still
  returns 0 files and the same skip: the ignore wins over an explicit path, deliberately, because the file may
  only ever make a scan read less. The contract and the glossary both say so now.
- **The rule's boundary is written down**, so whoever widens `ls-12` next meets the reason it was narrowed
  before changing it: [`docs/notes/legacy-scan-parity.md`](../notes/legacy-scan-parity.md).

## 📦 Package

- **256 files, 907 kB packed, 2.7 MB unpacked** (measured by `npm pack --dry-run`) — no file
  added or removed, still **zero** runtime dependencies, Apache-2.0, and **244 tests in 15 files** (243 passed
  plus one symlink-walk test that skips itself where the host forbids creating symlinks).
