# 0.7.0 — a panel that maps the counters, and a scan anyone can run 🗺

The sidebar panel stops being a scoreboard and becomes a map: how much was called and how well it went, when, from which
tool and with which outcome, which rules the scanner matched and which guides that points at. Its hit rate now divides by
the calls that could hit, so a week of catalog browsing no longer reads as a week of failed searches; the old number stays
in the tooltip. The scanner gains `/guidance-scan` for people — the panel's button is that command — a chat table for its
findings, and a last-scan record. Corpus, tools, rule table and guarantees are unchanged.

## ✨ Features

- **The panel answers four questions, in order.** *How much, and how well*: total calls and a hit rate over the calls
  that could hit — search hits, misses, unknown ids — with the report's all-calls rate in the tooltip; a `7 d` / `30 d`
  switch re-reads the window. *When*: one bar per day. *With what, and how it ended*: calls by tool and by outcome.
  *What the scanner catches*: the last completed scan, the rules that matched most (up to 10) and the guides they point at.
- **Below the map, the lists the report already had**: top queries with hits and misses, category coverage against the
  208 guides, the queries that found nothing, and the dead guides — now by id, up to 20, instead of a bare count.
- **`/guidance-scan <paths> [--rules ls-01,ls-13] [--format summary|json]`**, plus the panel button that runs
  `/guidance-scan .` for you. Paths are mandatory — no `.` default, no whole-workspace walk by accident — and the
  refusals, caps and text are the tool's own: the command reuses its scanner and its renderer, not a second copy.
- **Scan results in the conversation** render as a table rather than a JSON blob: rule, place, confidence and the guide
  that fixes it, up to 16 rows and "and N more", read back out of whichever format the call asked for.

## 🧪 Behaviour changes

- **The hit rate means something narrower, and reads higher.** `/guidance-stats` still divides hits by every call, `list`
  and `error` included; the panel divides by the calls that could hit, and keeps the report's number in the tooltip.
- **The report prints the scan detail**: `Most matched rules: …` and `Last scan: …` (when, files read, findings), so the
  rule and guide counts the panel draws also have a text form in the terminal.
- **A scan run from a command counts like a scan run by the tool.** Before, the panel's button showed a fresh result while
  `lastScan` stayed stale; both entry points now record through one recorder, so `byTool['legacy-scan']`, the finding
  totals and the last-scan line move either way.

## 🛠 Hardening

- **The panel cannot leak a path or a snippet**: the counters carry ids and numbers, the rows the command aggregates carry
  only `ruleId`/`guideId` with counts, and the panel has no field to render. Files and lines stay in chat and terminal.
- **The scan button cannot wander**: it sends `.`, and the command refuses to run without at least one explicit path, so
  neither an empty line nor a stray `--rules` can start a walk over the workspace.
- **A refused scan is an answer, not a crash**: `path-absolute`, `path-outside`, `path-missing` and `unknown-rules` print
  as text even under `--format json`, and a refusal is counted as an error call that does not overwrite the last scan.

## 🧩 Compatibility

- **Old state files keep loading as they are.** The document version stays `1`; `scanRules`, `scanGuides` and `lastScan`
  are additive, so a file written before they existed reads them as empty. Aggregates are never trimmed; only `lastScan`
  follows the retention window, because a scan nobody can place in time is not a counter.
- **`enabled: false` still means "no counters"**: `/guidance-stats` disappears and nothing is written, while
  `/guidance-scan` keeps working and printing, because scanning is not counting.
- **Two human commands now**, both out of the model's tool list; the four tools, schemas and caps are untouched, and the
  engines are unchanged (DSH `>=0.2.0-rc.1 <0.3.0-0`, Node `>=22.19.0`). The client half is still one hand-written file
  in three languages, and the panel still needs the host's `slots`, `locale` and `remote`.

## 📦 Package

- **256 files, 893 kB packed, 2.6 MB unpacked** (measured by `npm pack --dry-run`) — the file list did not change: the
  panel and the command are source in files that already shipped, so the tarball gained no asset and no dependency.
- Still **zero** runtime dependencies, Apache-2.0, sigstore provenance from the release workflow.
