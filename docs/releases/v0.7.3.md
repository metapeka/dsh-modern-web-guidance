# 0.7.3 — the panel stops quoting a scan without its caveats 🧾

0.7.2 taught the scan's own text to say what it skipped. The panel draws its summary from the same JSON,
and it was still printing a count with no word about the paths the walk never read: a live run showed
`Просканировано 70 файлов, 97 замечаний` and nothing else. Both caveats are now on screen, on all three
surfaces the panel owns. Same tool, same arguments, same caps, no new dependency.

## ✨ Features

- **The button's answer says what it did not read.** Under `Scanned 70 files, 97 findings` the panel now
  prints `Skipped 280 (278 extension, 2 dot-directory)`, naming the top three reasons and adding `+N more`
  inside the parentheses when a scan skipped for more — and nothing at all when nothing was skipped.
- **The last-scan line carries the same two facts, shorter.** `Last scan: 2026-11-10 · 70 files · 97
  findings · skipped 280 · truncated` — the total and the flag only, never the breakdown.
- **The chat tool row adds the skip line under its table**, for a JSON **and** a summary answer: the
  summary format prints `Skipped 280 path(s): 278 extension, 2 dot-directory` as prose and the row parses
  that line back, so one reader serves both formats and no second implementation appears.
- **Truncation reuses the 0.7.0 string** — `Truncated: the scan hit a cap, so this list is incomplete.` —
  because a second wording for the same fact is a second thing to keep in sync. There is no fifth key.

The counts differ between workspaces, and that is the point of them: a live run of this repository from
the GUI reported 280 skipped paths, a clean checkout reports 279, and neither is wrong — a scan counts
what is in the directory when it runs, so a `.tmp` scratch file or a harness service file is one more
skipped path like any other.

## 🧪 Behaviour changes

- **`lastScan` grows from four keys to six** — `{ at, files, findings, rules, skipped, truncated }`.
  `skipped` holds the **top four** reasons (count descending, then name), `{}` when nothing was skipped;
  `truncated` is true when the run stopped at any cap. `version` stays `1`: the fields are additive.
- **The printed sum is the sum of the four reasons the state kept.** A scan that skipped for five or more
  reasons prints fewer than its own `skippedTotal`, because the state document is a summary: keeping all
  eight reason rows would make every state file carry a scan's whole skip table. That is the contract, not
  a rounding bug — the fresh scan result, the button, the chat row and the tool's own text still carry every
  reason and its own total. The long-form contract is in
  [`docs/notes/legacy-scan-contract.md`](../notes/legacy-scan-contract.md).
- **A stale `stats.json` upgrades silently.** A 0.7.2 file has neither field, so the first report renders
  the shorter line — no `skipped 0`, no invented `truncated` — and the next completed scan rewrites the
  document with six keys. No migration step, no `version` bump, nothing to run by hand.
- **A refusal still leaves `lastScan` alone**, on the tool and on the command alike: an error is counted
  as an error call, and the stored summary keeps describing the last scan that actually finished.

## 🧩 Compatibility

- **Reason tokens are never translated**, on any surface: `dot-directory` stays `dot-directory` in EN, RU
  and ZH, exactly as a rule id stays `ls-13`. They are values a reader matches against a scan.
- Still one hand-written client file, still no host method and no new dependency; the data was already in
  the answer the panel received. Nothing to enable or configure.
- No path and no snippet appears anywhere new: the three surfaces show counts and reason names only, and
  the chat table remains the one place where files and lines appear.

## 📦 Package

- **256 files, 905 kB packed, 2.6 MB unpacked** (measured by `npm pack --dry-run`) — no file added or
  removed, still **zero** runtime dependencies, Apache-2.0, and **234 tests in 15 files** (233 passed plus
  one symlink-walk test that skips itself where the host forbids creating symlinks).

  `Skipped 280 path(s): …` 会被同一个读取器反解回来。
- `stats.json` 里的 `lastScan` 从四个键变成六个（`at, files, findings, rules, skipped, truncated`），状态
  版本仍是 `1`：`skipped` 只保留前四个原因，`truncated` 表示扫描是否触到任一上限。
- 因此打印出来的总数是「保存下来的四个原因」之和：原因达到五个以上时，它会小于扫描自身的 `skippedTotal`。

- 旧的 `stats.json` 会静默升级：缺少字段时按 `{}`/`false` 处理，那一行只是更短；下一次完成的扫描会用六个键
  重写文件。原因名在任何地方都不翻译，就像规则 id。
