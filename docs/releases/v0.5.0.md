# 0.5.0 — a legacy-pattern scanner you can trust to be modest 🔍

The fourth tool arrives: **`web_guidance_legacy_scan`** walks paths you name inside the session
workspace and reports line-level legacy markers against **30 rules**, each pointing at the guide that
shows the modern replacement. It is a marker scanner, not an AST analyzer: report-only, zero
dependencies, explicit about what it cannot see. The corpus and the three earlier tools are unchanged.

## 📚 Corpus

- Unchanged: the same **208 guides** (snapshot `2026_11_09-5bcc021b`), byte-identical to the previous
  snapshot, with no re-vendor.
- The rules are metadata over guides already in `data/guides.json`; the scanner never reads the corpus.

## ✨ Features

- **Fourth tool** `web_guidance_legacy_scan`: 1–16 explicit relative paths inside the workspace, an
  optional `rules` filter, and `summary` or `json` output.
- **30 rules** over **30 of the 208 guides** (14.4 %): 15 high, 13 medium, 2 low confidence. A finding
  carries `path:line:column`, the rule, its guide, the confidence, one imperative fix and a snippet.
- **Containment is a refusal, not a silent skip**: absolute paths, paths resolving outside the
  workspace, missing paths and unknown rule ids each return a named error saying what to pass instead.
- **Caps**: 16 paths, 200 files, 512 KiB per file, 8 MiB total, 200 findings; binaries and build
  directories are skipped, and symlinked directories are never entered.
- **Panel and report**: a fourth counter, `Legacy scans`, plus `Findings`; `/guidance-stats` reports
  scans and findings in text and `--json`.

## 🧪 Behaviour changes

- `/guidance-stats --json` gains `tools['legacy-scan'] = { total, files, findings }` and a `findings`
  total; a 0.4.x state file without the counter renders exactly as before.
- Scan outcomes are `findings` or `clean` instead of hit or miss; an errored scan is still counted.
- Search, retrieve and list output is untouched.

## 🛠 Hardening

- Read-only by construction: no write, spawn or network API; rule sources compile once and match one
  line at a time, and snippets are clipped and escaped, so a scanned file cannot smuggle control bytes
  into a report.
- Every named path is `realpath`-checked against the workspace; walking skips a symlink that escapes.
- The limit of a marker scanner is stated in the tool's own description: no AST, no automatic fixes,
  no parity with upstream's engine. A clean result means "none of these 30 markers matched".

## 🧩 Compatibility

- Engine ranges unchanged: DSH `>=0.2.0-rc.1 <0.3.0-0`, Node `>=22.19.0`.
- The tool appears in `Tool.listTools` like the other three; no new dependency, no build step.
- State files written by 0.4.x are read as-is; the fourth counter starts at zero.

## 📝 Skills and docs

- `AGENTS.md` gains the four-tool map and the rule that a new scan rule lands in `lib/scan-rules.js`.
- `GLOSSARY.md` defines legacy scan, marker scanner, rule, finding and confidence; `docs/README.md`
  maps the scanner modules and both 0.5.0 notes.
- `audit/security.md` documents the new read surface, with a runnable `path-outside` refusal.

## 📦 Package

- **256 files**, **873 kB packed**, **2.5 MB unpacked**; the growth is `lib/scan.js`,
  `lib/scan-rules.js` and the `index.js` / `client.js` wiring.
- Still **zero** runtime dependencies, Apache-2.0, with sigstore provenance from the release workflow.
